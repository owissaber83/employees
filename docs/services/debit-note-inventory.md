# حركات المخزون — الإشعار المدين (Phase 7 Step D)

## 1. الاتجاه والغرض

مرتجع مشتريات ⇒ البضاعة **ترجع للمورد**: حركة `type: 'out'` بسبب `purchase_return`.

## 2. 🔴 التقييم — سعر السطر مباشرةً، لا المتوسط المتحرّك

```js
unitPrice: parseFloat(line.unitPrice) || 0
```

**`calcInvItemMovingAvg` لا تُستدعى إطلاقاً في هذا المسار القديم.** أُثبت ذلك تشغيلياً
لا افتراضاً (`tests/golden-master/debit-note.test.mjs §[5]`): على نفس البيانات التي
تُنتج متوسطاً متحرّكاً 86.667، تكتب الحركة المدينة **750** (سعر سطر الفاتورة).

### هل هذا خطأ؟ — لا قرار هنا

**الحجّة للإبقاء:** سطر فاتورة المشتريات يحمل سعر **الشراء** أصلاً، فالمرتجع للمورد يخرج
بنفس التكلفة التي دخل بها. سليم اقتصادياً للمرتجع الفوري.

**الحجّة للتغيير:** إن كان الصنف قد اختلط بمشتريات أخرى بأسعار مختلفة، فالتقييم الجاري
بالمتوسط المتحرّك، وإخراج كمّية بسعر مختلف عنه **يُحدث انحرافاً دائماً في قيمة المخزون**
— بمقدار `qty × (سعر السطر − المتوسط الجاري)`.

⇒ **قرار محاسبي معلّق D4.** لم يُحسم ولم يُنفَّذ. السلوك القديم محفوظ حرفياً.
**لا تُوحَّد السياستان بلا قرار مالك** — التوحيد يغيّر قيمة المخزون في القوائم المالية.

## 3. حقول الحركة — منقولة حرفياً

```
number      OUT-{year}-{00001}   ← محجوز بمعاملة عدّاد
date        = تاريخ الإشعار
type        'out'       reason 'purchase_return'
itemId      qty         (الصفر لا يُرفض)
unitPrice   = سعر السطر (انظر §2)
projectId   description 'مرتجع مشتريات - إشعار مدين {رقم}[ - {وصف}]'
sourceType  'debit_note'         sourceKey {مفتاح الإشعار}
createdAt   createdBy
```

⚠️ غائب عمداً: `warehouseId` · `salePrice` · `notes`.

## 4. 🔴 لا فحص كفاية رصيد — والخروج قد يُنتج رصيداً سالباً

بخلاف حركة البيع (`createInventoryMovementsForSInv`) التي تُحذّر عند نقص الرصيد،
**الإشعار المدين لا يفحص شيئاً**. إخراج كمّية تتجاوز الرصيد يمرّ بصمت.
سلوك قائم محفوظ (صنف A) — تغييره قرار مالك لا قرار ترحيل.

## 5. قواعد التخطّي والاتساق

مطابقة للإشعار الدائن حرفياً (لا `itemId` · صنف غير موجود · خدمي · كمّية صفر تُكتب).
والاتساق مع القيد مطابق: كتابة ذرّية واحدة تضمّ المستند والقيد وكل الحركات، أو لا شيء.

## 6. حدود معروفة

نفس حدود الإشعار الدائن (§6 هناك)، عدا أن `planDebitNoteMovements` **لا تُقيّم** فهي
خطّية في عدد السطور فقط — بلا مسح لسجل الحركات. هذا الفارق في الأداء انعكاسٌ مباشر
للفارق المحاسبي في §2.
