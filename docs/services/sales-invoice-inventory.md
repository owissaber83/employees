# حركات المخزون في ترحيل فاتورة المبيعات (Phase 7 Step C)

## 1. الحقيقة الأولى — لا قيد محاسبي للمخزون

`createJournalForSInv` **لا تُنتج أي سطر مخزون أو تكلفة بضاعة مباعة**. تحقّقنا من ذلك
بقراءة الشفرة الحيّة لا بالافتراض:

- المشتريات تُصرَف مباشرة إلى حساب مصروف (`debitAccountCode` في `createJournalForPInv`).
- المخزون يُتابَع كمّياً وقيمياً في `ledger/inventoryMovements` فقط.
- لا حساب `114x` (مخزون) ولا `51x/52x` (تكلفة مبيعات) في أي قيد بيع.

⇒ النظام **جرد دوري** لا مستمر. أي إضافة قيد COGS = **تغيير في السياسة المحاسبية**،
وهو ممنوع في مرحلة الاستخلاص. مسجَّل كقرار معلّق **D2**.

مُثبَت في `postSalesInvoice.inventory.test.mjs §[7]`.

## 2. مجموعة كتابة المخزون

| المسار | متى | الآلية في الجديد |
|---|---|---|
| `ledger/counters/invmov/out/{year}` | مرّة لكل حركة | `runTransaction` منفصلة (خارج الذرّية) |
| `ledger/inventoryMovements/{id}` | مرّة لكل حركة | **ضمن الكتابة الذرّية الواحدة** |

## 3. قواعد التخطّي — منقولة حرفياً

سطر الفاتورة يُتخطّى إن: لا `itemId` · الصنف غير موجود · `item.type === 'service'`.

| الحالة | القديم | الجديد | صنف |
|---|---|---|---|
| كمّية = 0 | يكتب حركة بكمّية 0 | نفسه | A |
| رصيد غير كافٍ | تنبيه فقط، الحركة تُكتب (يسمح بالسالب) | نفسه + تحذير **مُعاد للمستدعي** لا `toast` | A |
| صنف خدمي | يُتخطّى | نفسه | A |
| فاتورة بلا سطور | لا حركات، الترحيل يتم | نفسه | A |

## 4. حقول الحركة

```
number      OUT-{year}-{00001}        ← محجوز بمعاملة عدّاد
date        = تاريخ الفاتورة
type        'out'          reason 'sale'
itemId      qty            (بلا رفض للصفر)
unitPrice   = تكلفة الخروج (انظر §5)
salePrice   = سعر بيع السطر (للمرجعية)
projectId   = مشروع الفاتورة ‖ ''
description 'بيع - فاتورة {رقم}[ - {وصف السطر}]'
notes       'مرتبط تلقائياً بفاتورة مبيعات {رقم}'
sourceType  'sales_invoice'           sourceKey {مفتاح الفاتورة}
createdAt   createdBy
```

⚠️ **`warehouseId` غائب تماماً** — القديم لا يكتبه، و`whIdOfMovement` تُرجع الحركة إلى
المخزن الرئيسي عند القراءة. محفوظ حرفياً ومُختبَر (`gm 28` · `inventory [1]`).

## 5. تكلفة الخروج (COGS) — سلسلة الرجوع

```
calcItemMovingAvg(...).avgCost  إن > 0
  ←  item.costPrice
  ←  line.unitPrice
  ←  0
```

المتوسط المرجّح **المتحرّك** (Perpetual Moving Weighted-Average) لا المتوسط التراكمي —
لأن الأخير يُنتج تكلفة خاطئة بعد أي دورة رصيد صفري ثم شراء لاحق بسعر مختلف. نُقلت
الدالة حرفياً إلى `src/domain/inventory/movingAverage.js` وأُثبتت بالمقارنة الفعلية مع
القديم على 9 عوالم (`npm run test:char:inventory` — 49 تأكيداً)، منها دورة الرصيد الصفري
نفسها والإخراج الزائد والمخازن المتعدّدة والفرز الزمني.

⚠️ **اللقطة ثابتة أثناء التخطيط**: كل سطر يُقيَّم على نفس لقطة الحركات، ولا تُضاف حركات
هذه الفاتورة إلى الحساب أثناء الحلقة. هذا سلوك القديم حرفياً (`window.inventoryMovements`
لا تتحدّث إلا بحدث `onValue` لاحق) — محفوظ عمداً، لا سهواً.

## 6. الاتساق مع القيد

| الحالة | النتيجة |
|---|---|
| نجاح | قيد + ربط + **كل** الحركات — في كتابة ذرّية واحدة |
| فشل | لا قيد · لا حركة · لا ربط · الحالة تعود `draft` |
| طلب مكرّر | لا قيد ثانٍ · لا حركة ثانية · لا نقص مخزون مضاعف |

القديم بالمقابل: كل حركة `push` مستقلّ داخل `try/catch` يبتلع الخطأ (`console.error` فقط)
⇒ فشل حركة واحدة يترك الفاتورة مرحّلة بحركات ناقصة **بصمت**. فرق **C6**.

## 7. الحدود المعروفة

1. **عدّاد الحركات لا يُبذَر** من `window.inventoryMovements` كما يفعل القديم — البذرة
   لقطة متصفّح لا تملكها طبقة المستودع. الأثر: على قاعدة بلا عدّاد سابق يبدأ الترقيم من
   1 وقد يصطدم نصّياً بأرقام قديمة. **ترقيم لا مال** — فرق **B2**.
2. **N معاملة عدّاد لكل ترحيل** (واحدة لكل حركة) — نفس القديم. مصدر رئيسي لزمن الشبكة.
3. **تخطيط المخزون O(سطور × حركات)**: كل سطر يُعيد مسح سجل الحركات كاملاً. منقول حرفياً
   من القديم؛ التحسين مؤجَّل عمداً — الاستخلاص لا يُغيّر السلوك.
4. **لا فحص مانع للرصيد السالب** — سلوك قائم (A)، وتغييره قرار مالك لا قرار ترحيل.
