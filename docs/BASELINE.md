
**النشر التلقائي:** الدفع إلى `main` يُطلق `.github/workflows/firebase-hosting-merge.yml` فينشر `public/` إلى الإنتاج. **قواعد قاعدة البيانات لا تُنشَر عبر CI إطلاقاً.**

### 2.1 الاختبارات الخمسة الحمراء — تشخيص كامل

**ليست ثغرة أمنية. هي ميزة معطّلة.**

الفاشلة: قراءة الزائر للقطة البوابة · إلحاق ردّ اعتماد · إلحاق إجابة RFI · قراءة العضو لصندوق الردود · إنشاء لقطة بوابة.

**السبب المؤكّد:** `database.rules.json` يحوي **صفر** إشارة إلى `portal`، بينما الاختبارات تتوقّع مسارَي `portalSnapshots` و`portalResponses`. قواعد البوابة **لم تُكتب قط**.

**التقييم الأمني:** ✅ **فشل آمن.** الاختبارات الستّة من نوع `assertFails` (منع التزوير، منع الإجراءات غير المسموحة) **تمرّ كلها** — لأن كل شيء ممنوع. لا باب مفتوح.

**الأثر التشغيلي:** 🔴 واجهة البوابة **موجودة وحيّة** (9 إشارات في `app.js` و`project-detail.js`، ومسار `#portal=` مُفعَّل). أي أن ميزة بوابة المشروع **معطّلة فعلياً في الإنتاج** — الزائر يتلقّى `permission_denied`.

**القرار:** خارج نطاق هذا المشروع. لا يُصلَح ضمن الترحيل (تغيير قواعد أمان يخضع لـ§6). يُرفع إليك كبند مستقل.

**استخدامه كخط أساس:** إن بقيت هذه الخمسة حمراء بعد أي مرحلة ⇒ لا انحدار. إن صار العدد 6 ⇒ توقّف وحقّق.

## 5. إجراء التراجع (Rollback)

### 5.1 التراجع الكامل إلى ما قبل الترحيل

```bash
git checkout migration/baseline      # الوسم المثبَّت في Phase 1
```

النظام يعود كما كان تماماً: لا خطوة بناء، لا أصول مولّدة، لا شيء يجب التراجع عنه في قاعدة البيانات — **لأن هذا المشروع لا يغيّر المخطّط إطلاقاً**.

### 5.2 التراجع عن مرحلة واحدة

```bash
git revert <commit>                  # كل مرحلة إيداع مستقل
```

### 5.3 لماذا التراجع رخيص هنا

| | |
|---|---|
| مخطّط قاعدة البيانات | لا يتغيّر ⇒ لا ترحيل بيانات ⇒ لا تراجع بيانات |
| مصدر الحقيقة | Firebase RTDB وحده طوال المشروع |
| Dual Write | ممنوع ⇒ لا مزامنة يجب فكّها |
| النظام القديم | يبقى عاملاً حتى نهاية المشروع |

### 5.4 نسخ البيانات — 🔴 فجوة قائمة

`dailyBackup` غير منشورة (خطة Spark). البديل الوحيد `downloadLocalBackup` **يعمل فقط حين يفتح مدير التطبيق**. لا نسخ خادمي مجدول.

**هذا لا يمنع الترحيل** (لأننا لا نلمس البيانات)، لكنه خطر تشغيلي قائم يجب أن تعرفه.
